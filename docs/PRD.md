## 2. 产品定位

`rag-app` 是一个本地数据、在线模型、可复用、模块化的通用 RAG 知识库工作台。核心场景是“知识证据问答”：用户把 Markdown、纯文本、PDF、Word 或 HTML 资料入库，系统抽取文本、切块、向量化、检索、重排并筛选证据，再基于可追溯证据生成答案。

本项目不绑定智能客服、路由器产品或任何特定行业。第一版使用现有 6 份产品 Markdown 作为端到端验收资料，但核心 API、数据模型和页面文案保持通用。

现有 `rag-lab` 继续承担课程教学和离线实验职责；`rag-app` 独立演进为更完整的可复用项目。课程站负责讲解并链接到工作台，不承载工作台业务。

## 3. 背景与问题

当前已有两类资产：

1. `rag-lab` 已具备教学型五阶段流水线，包括标题切块、JSON 向量索引、检索重排、TopK 证据、生成、CLI、FastAPI 和离线评测。
2. 本地参考项目已验证 SQLite、Chroma、多知识库、上传管理、千问模型、语义证据判定、局部拒答和 SSE 的可行性。

教学项目偏重可读性和离线实验，缺少真实持久化和工作台生命周期管理；参考项目偏客服场景，复用性受场景文案和架构历史影响。`rag-app` 需要在两者基础上形成清晰边界：通用项目、真实数据面、可替换模型适配层和可审计证据链。

## 4. 产品目标

1. 支持多知识库、Markdown / 纯文本 / PDF / Word / HTML 上传、文档删除、重复拦截和示例资料一键导入。
2. 仅支持 online 运行模式；模型配置缺失时禁用入库与问答，并返回安全配置错误，不降级为本地规则模式。
3. 支持从多格式文档入库到证据生成回答的完整链路。
4. 区分“相关资料”和“足以直接回答的证据”。
5. 支持复合问题拆分、局部拒答、生成后校验和最多一次重生成。
6. 提供证据来源、标题路径、分数、子问题和执行阶段，保证答案可审计。
7. 建立固定评测集，防止检索、拒答和证据质量退化。
8. 保持本地单实例、无登录、可控依赖，后续可扩展但不推翻核心数据模型。
9. 上传采用进程内线程池异步任务，工作台可轮询逐文件阶段进度，避免大文件阻塞请求。
10. 提供数据面备份与恢复命令，使 SQLite、uploads 与 Chroma 可整体快照和回滚。
11. 提交阶段快速校验文件名、扩展名、大小和数量；工作台支持取消任务和重新提交失败文件。

## 5. 用户与使用场景

### 5.1 目标用户

- **知识库管理员**：创建知识库，导入或上传 Markdown / 纯文本 / PDF / Word / HTML，检查处理结果，删除过期资料。
- **知识使用者**：选择一个或多个知识库提问，查看答案、执行过程、证据和拒答原因。
- **开发与课程维护者**：运行自动化回归、在线验收、一致性检查和索引重建。

第一版不实现账号、角色和权限隔离。以上角色只用于描述使用目标，同一本地用户可以操作全部功能。

### 5.2 核心场景

1. 用户创建“产品资料”知识库。
2. 用户一键导入 6 份示例 Markdown，系统执行校验、切块、向量化和入库。
3. 用户上传 PDF、Word 或 HTML 文档，系统抽取文本后走同一套切块、指纹和向量化流程。
4. 上传以异步任务提交，用户在工作台看到每份文件的“校验 / 切块 / 向量化 / 保存 / 完成”阶段进度。
5. 用户可以在排队或阶段边界处取消任务；已完成的文件保留，未开始或已取消的文件不入库。
6. 用户对失败文件点击“重新提交失败文件”，浏览器使用仍在内存中的 File 对象提交一个全新 job；服务端不保留重试状态。
7. 用户重复上传规范化后内容相同的文档，系统在调用 Embedding 前拦截。
8. 用户选择一个或多个知识库提问。
9. 系统拆分复合问题，分别检索和判定证据。
10. 有证据的部分生成引用编号答案；缺少证据的部分局部拒答。
11. 用户查看证据的文档名、标题路径、分数、子问题和证据状态。
12. 用户删除文档或知识库后，相关内容不可再次检索。
13. 开发者运行固定评测集和 doctor 检查，确认无退化或数据不一致，必要时用 backup / restore 回滚数据面。

## 6. 范围

### 6.1 P0 范围

- 知识库创建、列表、选择和删除。
- Markdown / 纯文本 / PDF / Word / HTML 文档上传、列表、删除。
- 异步上传任务：提交返回 job，工作台轮询逐文件阶段进度，可取消任务并重新提交失败文件。
- 空库启动与示例资料一键导入。
- SQLite 保存业务元数据。
- Chroma 保存向量与 chunk 检索元数据。
- 本地 uploads 目录按原扩展名保存原始文件。
- 多格式校验与文本抽取、规范化、内容指纹、标题感知切块和超长递归切块。
- 同库内容去重，跨库允许相同内容。
- 多知识库检索范围过滤。
- Chroma 候选召回、重排、TopK 证据。
- 问题改写与拆分。
- 语义证据判定。
- 证据内生成、引用校验、数字校验和证据支持校验。
- 局部拒答、全部拒答和一次重生成。
- React 工作台：概览、知识库、问答三个页面。
- SSE 阶段事件和校验后最终答案。
- 基于 Fake Provider 的自动化回归，仅存在于测试环境。
- online 连通性与人工验收。
- doctor 一致性检查和 rebuild 索引重建。
- backup / restore 数据面快照与恢复。
- FastAPI 固定端口托管前端构建产物。

### 6.2 非目标

- 不做登录、角色、权限、多租户和公网部署。
- 不做网页抓取、浏览器采集或 OCR；扫描版 PDF 不保证可抽取文本。
- 不做文档 Adapter 插件市场。
- 不做多模型动态切换 UI。
- 不做 Celery、Redis 或跨进程持久化的任务队列；异步上传仅使用进程内线程池，服务重启后任务状态不保留。
- 不做对话历史长期保存、搜索或导出。
- 不做评测后台、系统日志页面或运营报表。
- 不做人工客服转接、工单或满意度评价。
- 第一版不引入 LangGraph。
- 第一版不做动态工具选择或多 workflow 路由实现，仅预留扩展点。

## 7. 运行模式

### 7.1 唯一产品运行模式：online

`rag-app` 对用户只提供 online 运行模式。有效模型配置是入库和问答的前置条件；配置缺失或无效时，服务可以返回安全配置错误并禁用相关操作，但不得降级为本地规则模式。

- Chat 和 Embedding 使用 OpenAI-compatible HTTP 接口。
- Rerank 暂定 `qwen3-rerank`。
- Rerank 服务地址可配置，后续可替换为性价比更高的 API。
- 模型调用统一经过轻量 Provider Adapter，对内暴露 `embed / chat / rerank` 能力。
- 第一版不依赖 LangChain 或 LangGraph。

### 7.2 测试 Fake Provider

自动化测试可以使用依赖注入的 Fake Provider 提供确定性向量、重排、生成、语义判定和校验结果，用于验证业务编排、数据一致性和接口契约。

Fake Provider 只存在于测试代码和测试装配中：

- 不提供环境变量或命令行开关。
- 不创建第二套产品数据目录。
- 不在 UI 中显示为 offline 或演示模式。
- 不替代 online 模型质量验收。
- 不被称为“离线模式”。

### 7.3 密钥安全

- API Key 只通过 `.env` 注入。
- API Key 不进入源码和 Git。
- API Key 不返回给前端。
- API Key 不出现在状态接口、SSE、页面、异常消息或日志中。

## 8. 数据架构

### 8.1 单一数据目录

产品运行时只使用一套数据目录，保存当前 online 配置对应的业务事实与向量索引。

```text
rag-app/
├── data/
│   ├── app.db
│   ├── chroma/
│   ├── uploads/
│   └── spool/
```

启动时校验当前索引记录的模型名和向量维度。测试如需隔离数据，应使用临时目录和 Fake Provider，而不是产品级 offline 数据目录。

### 8.2 存储责任

| 存储 | 保存内容 | 主要责任 |
| --- | --- | --- |
| SQLite | 知识库、文档、内容指纹、状态、路径、chunk 数量、时间 | 业务事实与审计 |
| Chroma | 向量、chunk 内容、`kb_id`、`document_id`、标题路径等 metadata | 相似度检索与范围过滤 |
| uploads | 原始上传文件（保留原扩展名） | 人工回看、审计和索引重建 |

SQLite 元数据和原始上传文件是业务事实；向量索引是可重建的派生数据。`spool/` 只保存异步任务处理期间的临时原始字节，任务结束即删除；服务启动时清理上次进程遗留的 spool 文件。spool 不属于业务事实。

### 8.3 模型或维度变更

当启动时检测到模型名或向量维度与当前数据目录配置不一致：

1. 拒绝启动。
2. 返回安全、明确的配置错误。
3. 提示用户运行 `doctor` 检查。
4. 如需重建，提示用户运行 `rebuild` 并明确确认。

系统不得自动清空数据目录，也不得混用不同 Embedding 空间。

## 9. 知识库与文档管理

### 9.1 知识库

- 支持创建、列表和删除知识库。
- 知识库名称必填、去首尾空白，且不允许重复。
- 删除前必须确认。
- 删除知识库必须同时删除其文档元数据、原始文件和全部向量。
- 删除一个知识库不得影响其他知识库。

### 9.2 初始数据

系统首次启动为空库，不默认写入业务数据。

工作台提供“一键导入示例资料”能力，导入现有 6 份 Markdown，并完整执行：

```text
校验
→ 规范化
→ 内容指纹
→ 去重检查
→ 切块
→ 向量化
→ 保存原文件
→ 写入向量
→ 写入元数据
→ 列表展示
```

### 9.3 上传限制

- 接受扩展名 `.md`、`.txt`、`.pdf`、`.docx`、`.html`、`.htm`。
- 文本类文件（`.md` / `.txt` / `.html` / `.htm`）必须能以 UTF-8 解码。
- PDF、Word、HTML 先经对应抽取器转为纯文本；抽取结果为空则按空文档拒绝。
- 单文件上限 5 MB。
- 单次最多 20 个文件。
- 异步提交阶段先完整校验文件名、扩展名、大小和数量；任一项非法时不创建 job。
- 空文档、扩展名错误、解码错误和解析失败必须在向量化前拒绝。

### 9.4 异步处理

上传采用进程内线程池异步任务：

- 提交接口立即返回 `job_id`，不等待入库完成。
- 提交阶段完成文件名、扩展名、大小和数量预检，非法请求快速失败且不创建 job。
- 内部按“校验、切块、向量化、保存、完成”报告进度。
- 批量上传支持部分成功、部分失败，失败项带错误码。
- 支持取消排队中或阶段边界处的任务；取消不会撤销已经写入的文档。
- 工作台通过轮询任务接口获取逐文件状态与进度，可发起取消和失败文件重新提交。
- 任务注册表保存在内存中，服务重启后历史 job 不再可查；`spool/` 临时文件随任务结束清理，服务启动时清理上次进程残留。
- 失败重试不保留在服务端；前端使用本次会话仍持有的 File 对象提交新 job。
- 不引入 Celery、Redis 等外部任务队列。

### 9.5 重复规则

- 对抽取并规范化后的文本内容计算 SHA-256。
- 同一知识库内内容相同即重复。
- 换行风格不同但内容相同仍视为重复。
- 重复检查必须发生在 Embedding 调用前。
- 不同知识库允许保存相同内容。
- 文件名仅作为展示名，不作为内容身份。

### 9.6 失败分类

至少区分：

- 空文档。
- 空文件名。
- 扩展名错误。
- 解码错误。
- PDF / Word / HTML 解析失败。
- 解析器不可用（例如缺少 PDF 依赖）。
- 同库重复文档。
- 切块失败。
- 向量化失败。
- 存储写入失败。

失败处理要求：

1. 失败文档不得以成功状态展示。
2. 失败文档不得可被检索。
3. 已产生的原文件、向量和元数据必须反向补偿清理。
4. 清理失败时返回明确的不一致提示。
5. 详细技术原因写入本地日志，日志不得包含 API Key。

## 10. RAG 问答流程

### 10.1 编排原则

采用显式 Python 阶段函数实现固定证据问答 workflow，并预留场景路由和 workflow registry 扩展点。

未来可扩展：

- 文档总结 workflow。
- 订单查询 workflow。
- 确定性计算 workflow。
- 轻量澄清 workflow。

但第一版只实现知识证据问答 workflow。产品事实、政策或售后规则类问题不得由模型自行决定是否检索或是否引用证据。

### 10.2 固定流程

```text
问题改写与拆分
→ 多知识库检索
→ 重排 TopK
→ 语义证据判定
→ 可回答项生成
→ 引用与数字校验
→ 必要时一次重生成
→ 合并回答 / 局部拒答
```

### 10.3 问题理解

- 使用当前前端会话历史改写问题。
- 复合问题最多拆分为 5 个子问题。
- 超过 5 项时只处理前 5 项，并说明范围限制。
- 使用结构化模型调用拆分。
- 拆分解析失败时回退为单个原问题。

### 10.4 检索与重排

- 每个子问题独立检索。
- 检索必须限制在用户选择的知识库范围内。
- 默认候选池为 `TopK * 20`。
- 重排后保留 Top 7。
- 使用配置的 rerank API。
- 未选择知识库时阻止提问。
- 检索结果不得泄漏未选择知识库。

### 10.5 证据判定

证据状态分为：

- `supporting`：回答证据，足以直接支持某个子问题。
- `related`：相关资料，但不足以直接回答。

判定要求：

- 每个子问题独立判定是否可回答。
- 只允许引用该子问题实际获得的候选证据。
- 判定输出非法、引用越权或缺失判定时，对该子问题保守拒答。
- 不使用相似度阈值单独代表“证据充分”。

### 10.6 生成与校验

- 只把可回答子问题及其直接证据交给生成策略。
- 不可回答子问题由程序生成固定局部拒答。
- 生成正文必须引用证据编号。
- 生成后校验至少包括：
  - 至少存在一个引用。
  - 引用编号属于该子问题允许的证据。
  - 回答中的数字事实能回溯到证据。
  - 结论由允许证据支持。
- 明确校验失败时允许携带失败原因重生成一次。
- 第二次仍失败时，仅降级失败子问题，不影响已验证部分。

### 10.7 会话历史

- 会话历史仅保存在当前前端会话中。
- 历史用于问题改写和指代消解。
- 刷新页面、新建会话或服务重启后不恢复历史。
- 历史不写入 SQLite。
- 后续版本再评估长期会话管理。

## 11. API 需求

### 11.1 Web API

第一版只暴露本地工作台所需接口：

- `GET /api/status`
- `GET /api/knowledge-bases`
- `POST /api/knowledge-bases`
- `DELETE /api/knowledge-bases/{kb_id}`
- `GET /api/knowledge-bases/{kb_id}/documents`
- `POST /api/knowledge-bases/{kb_id}/documents`
- `POST /api/knowledge-bases/{kb_id}/documents/async`
- `DELETE /api/knowledge-bases/{kb_id}/documents/{document_id}`
- `GET /api/jobs/{job_id}`
- `POST /api/knowledge-bases/{kb_id}/import-demo`
- `POST /api/chat/stream`

评测、doctor 和 rebuild 通过 CLI 提供，暂不作为公开 Web API。

### 11.2 SSE 契约

SSE 事件类型包括：

- 阶段状态事件。
- 检索证据事件。
- 语义判定事件。
- `answer_final` 最终答案事件。
- 完成事件。
- 安全错误事件。

约束：

- 未验证答案不得通过 SSE 输出。
- `answer_final` 只在生成和校验完成后发送。
- 不输出 token 级正文流。
- 不输出提示词。
- 不输出 API Key。
- 不输出本地路径。
- 不输出底层异常细节。
- 详细技术原因写本地日志，且日志不包含密钥。

## 12. 工作台需求

### 12.1 技术形态

- 独立 React + Vite 前端。
- FastAPI 同端口托管前端构建产物。
- 默认访问地址：`http://127.0.0.1:8010`。
- 开发阶段可前后端分离启动。
- 最终演示优先使用 FastAPI 同端口托管。

### 12.2 信息架构

页面采用三个核心入口：

1. **概览**。
2. **知识库**。
3. **问答**。

第一版不做单独评测页、模型配置页或系统日志页。

### 12.3 概览页

展示：

- 知识库数量。
- 文档数量。
- 文本块数量。
- 问答与知识库入口。
- 入库规则摘要。

概览页不展示运行模式、模型名称、API Key 明文或本地绝对路径；服务连接状态由全局状态标识展示。

### 12.4 知识库页

覆盖状态：

- 空知识库。
- 新建知识库。

## 13. CLI 与一致性

第一版提供：

- `serve`：启动本地服务。
- `eval`：运行固定评测。
- `doctor`：检查 SQLite、Chroma 和 uploads 一致性。
- `rebuild`：经用户确认后基于 SQLite 和原始上传文件重建向量索引。
- `backup [目录]`：把 app.db、uploads、Chroma 与 manifest 打包为单个 `.tar.gz` 快照，不包含 `.env`。
- `restore <归档> --yes`：从快照恢复数据目录，非空目录需显式确认。

`serve` 启动要求：

- 初始化统一安全日志，不输出 API Key、prompt、本地绝对路径或底层异常。
- 已有 SQLite 数据目录先执行 doctor；错误阻断启动，警告允许启动并提示。
- 全新数据目录允许首次初始化，不得被空库 doctor 误拦截。
- 前端构建产物缺失时给出构建提示，API 仍可启动。
- 端口占用或数据面初始化失败时返回安全、可行动的启动错误。
- FastAPI 生命周期退出或启动失败时关闭自持有的模型 Provider，且关闭必须幂等。

doctor 至少检查：

- 元数据文档数量与 chunk 数量。
- Chroma 中的文档和 chunk 关系。
- uploads 中缺失或多余的文件。
- 孤儿向量。
- 模型名和向量维度配置。
- 删除后残留向量。

## 17. 风险与约束

| 风险 | 影响 | 处理策略 |
| --- | --- | --- |
| 模型服务不可用或配置错误 | 入库和问答不可用 | 返回安全配置错误并禁用相关操作，不降级为本地规则模式 |
| online JSON 输出不稳定 | 拆分、判定或生成解析失败 | 使用保守回退和 fail-closed 局部拒答 |
| 三份存储不一致 | 删除后仍可召回或统计错误 | 失败补偿、doctor、幂等删除和一致性测试 |
| Embedding 模型或维度变更 | 混用向量空间导致检索不可信 | 启动拦截、doctor 提示、用户确认 rebuild |
| rerank API 成本或稳定性变化 | online 体验退化 | Provider Adapter 和配置化接口，允许替换服务 |
| 上传处理时间较长 | 用户等待明显、大文件请求易超时 | 采用进程内线程池异步任务并轮询进度，支持取消和前端重试，仍限制文件大小和批量数量 |
| 复合问题过复杂 | 子问题过多或拆分错误 | 最多 5 项，超限提示，非法输出回退 |
| 数据误删、迁移或索引损坏 | 业务数据不可恢复 | 提供 backup / restore 快照命令，改上传或切块逻辑前先备份 |
| PDF / Word 解析质量不稳定 | 抽取文本缺失或错乱 | 解析失败按失败项返回，不写入半成品；必要时人工回退为文本格式 |

## 18. 验收清单

- 空库启动。
- 创建知识库。
- 一键导入 6 份 Markdown。
- 查看每份文档文本块数量。
- 重复上传同内容被拦截。
- 上传空文档、错误扩展名和非 UTF-8 文件被拒绝。
- 上传 Markdown / 纯文本 / PDF / Word / HTML 均能入库并进入证据检索。
- 异步上传提交后立即返回 job，轮询可看到逐文件阶段进度与结果。
- 非法文件名、扩展名、大小或数量在提交阶段返回 400，且不创建 job。
- 服务重启后不遗留旧进程 spool 文件。
- 排队中或阶段边界处的任务可取消；已完成项保留，取消项不入库。
- 前端可重新提交失败文件，且每次重试都是新的异步 job。
- backup 生成的归档不包含 `.env`，restore 后 doctor 计数一致。
- 删除文档后不可检索。
- 删除知识库后不残留向量。
- 多选知识库检索不泄漏未选知识库。
- 知识库外问题全部拒答。
- 复合问题有证据部分回答，无证据部分局部拒答。
- 答案包含引用编号。
- 证据面板区分回答证据和相关资料。
- SSE 展示完整阶段流。
- 未验证正文不提前输出。
- Fake Provider 自动化回归全部通过。
- Fake Provider 回归 Top 7 命中率不低于 85%。
- online 配置缺失时给出安全提示并禁用入库与问答。
- online 配置有效时完成人工验收。
- API Key 不出现在前端、接口、SSE 或日志。
