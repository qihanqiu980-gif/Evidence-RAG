## 2. 设计定位

### 2.1 Design Read

这是本地单实例的知识生产力工作台，面向知识库管理员、知识使用者和开发维护者。视觉语言应是明亮、轻量、证据优先的浅色工具界面，而不是营销官网、智能客服或数据大屏。

设计方向概括为：**清爽证据工作台**。

- 页面以内容与状态为中心，装饰不参与表达。
- 白色卡片承载可操作对象，浅灰画布提供稳定的工作区。
- 问答页强调“回答、证据、执行过程”三者可回看。
- 所有失败和拒答都应清楚、保守、可理解。
- 密钥、模型名、本地路径和底层异常不进入界面。

### 2.2 设计强度

| 维度 | 取值 | 说明 |
| --- | ---: | --- |
| 视觉变化 | 3 / 10 | 产品界面对称、稳定、可预测，避免为了形式感破坏任务路径 |
| 动效强度 | 2 / 10 | 只保留状态反馈和轻量过渡，不使用滚动叙事或装饰动画 |
| 信息密度 | 6 / 10 | 偏生产力工具，保留呼吸感，但列表、证据和阶段流需要紧凑可扫读 |

## 3. 设计原则

1. **证据优先**：答案视觉权重最高，证据和执行过程可展开、可追溯，不能被装饰弱化。
2. **状态完整**：空态、加载、部分成功、重复、失败、拒答、配置错误均是一等界面状态。
3. **动作有边界**：新建、上传、删除、提问都明确可用或禁用原因。
4. **信息安全**：界面只展示用户可理解的安全信息，不出现 API Key、本地绝对路径、提示词或底层异常。
5. **轻量工作台**：使用边框和浅色分层，不依赖阴影、渐变和图像化装饰。
6. **中文优先**：文案直接、具体、可执行，避免口号化和拟人化。

## 4. 信息架构

### 4.1 全局结构

```text
应用外壳
├── 概览
├── 知识库
│   ├── 知识库列表
│   ├── 知识库详情
│   │   ├── 上传结果
│   │   └── 文档列表
│   └── 新建与删除确认
└── 问答
    ├── 检索范围
    ├── 会话消息
    ├── 证据面板
    ├── 执行过程
    └── 输入区
```

第一版只提供三个主导航入口：概览、知识库、问答。不新增模型配置页、评测页、日志页或系统设置页。

### 4.2 桌面布局

| 区域 | 规格 |
| --- | --- |
| 左侧导航 | 宽 `216px`，白色背景，右侧 `1px` 分隔线，垂直固定 |
| 内容区 | 最大宽度 `1200px`，水平边距桌面 `40px`，小屏 `24px` |
| 页面标题区 | 标题与说明在左，主操作在右；窄屏纵向堆叠 |
| 页面底部 | 轻量页脚，与内容区同宽，使用 `1px` 上边线分隔 |

### 4.3 响应式布局

| 断点 | 规则 |
| --- | --- |
| `< 768px` | 单列布局；页面主操作占满可用宽度；文档表优先显示文件名、状态和操作；标题和长文件名允许换行 |
| `768px` 至 `1023px` | 概览统计横排；知识库列表两列；问答保留单列会话 |
| `>= 1024px` | 启用固定左侧导航；知识库页采用 `280px + 自适应` 两栏；问答保留单列会话 |
| `>= 1280px` | 问答页采用 `自适应会话 + 360px 执行过程侧栏` 两栏；会话正文保持可读行宽，输入区与会话面板同宽 |

移动端导航使用顶部品牌行加横向导航项，不做隐藏式复杂菜单。

## 5. 视觉系统

### 5.1 色彩原则

主色只承担品牌、激活、主要动作和信息状态，不用于大面积背景。成功、警告、危险仅用于状态语义，不做装饰。

| Token | 值 | 用途 |
| --- | --- | --- |
| `--bg` | `#f6f7f9` | 应用画布，接近参考 1 的纸感但更冷，适合工具界面 |
| `--card` | `#ffffff` | 卡片、表格、输入框、导航面板 |
| `--surface-muted` | `#fafbfc` | 表头、会话输入区、展开面板背景 |
| `--neutral-soft` | `#eef0f3` | 中性徽章、用户消息、轻量填充 |
| `--ink` | `#1f2328` | 主文本 |
| `--muted` | `#5b6470` | 次级文本和说明 |
| `--line` | `#e3e6eb` | 默认分隔线和边框 |
| `--primary` | `#1f5fd1` | 主品牌、主按钮、激活导航、进行中阶段 |
| `--primary-soft` | `#eaf1fd` | 选中知识库、激活状态浅底 |
| `--ok` | `#1f6b45` | 已就绪、回答完成、证据充分 |
| `--ok-soft` | `#e9f4ee` | 成功徽章背景 |
| `--warn` | `#8a5a0f` | 配置错误、重复文档、局部拒答 |
| `--warn-soft` | `#fbf3e3` | 警告徽章和局部拒答提示背景 |
| `--danger` | `#b0342f` | 删除、失败、服务异常 |
| `--danger-soft` | `#fbeceb` | 危险徽章背景 |

正文、次级文本、主按钮、状态徽章需满足 WCAG AA 对比要求。状态色不作为唯一识别通道，必须与文字一起出现。

### 5.2 参考风格映射

| 来源 | 采纳 | 不采纳 |
| --- | --- | --- |
| 参考 1 Notion | 温和浅色画布、白色卡片、细边框、低阴影、层级克制的黑色系文本 | 大号营销标题、彩色功能卡、插画和角色装饰、多色背景、12px 以上卡片圆角 |
| 参考 2 Bevel | 明亮白色、云雾蓝浅面板、清爽分区、克制的数据色 | 24px 至 32px 大圆角、胶囊公共站导航、渐变 hero、产品渲染图、超大家庭式留白 |
| 现有原型 | 三页 IA、左侧导航、轻边框卡片、证据与执行过程的信息组织 | 运行时加载 Google 字体、临时品牌名和“UI 原型”产品化文案 |

### 5.3 字体

界面采用中文优先的系统字体栈，不依赖运行时外部字体服务。生产环境建议自托管字体；如果本地包体需要保持轻量，直接使用系统栈。

```css
--font-sans: -apple-system, BlinkMacSystemFont, "Segoe UI", Inter,
  "Noto Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif;
--font-number-variant: tabular-nums;
```

| 层级 | 字号 / 行高 | 字重 | 用途 |
| --- | --- | ---: | --- |
| 页面标题 | `24px / 1.35` | 600 | 概览、知识库、问答 |
| 区块标题 | `17px / 1.4` | 600 | 卡片、列表、面板标题 |
| 正文 | `15px / 1.6` | 400 | 描述、答案、空态文案 |
| 表格与控件 | `14px / 1.5` | 400 至 500 | 表格、按钮、输入、证据元信息 |
| 辅助说明 | `13px / 1.5` | 400 | 阶段说明、规则、时间、分数 |

中文不使用负字距。数字、时间、分数、chunk 数量启用 `tabular-nums`，保证列表刷新时稳定对齐。

### 5.4 间距与形状

| Token | 值 | 用途 |
| --- | ---: | --- |
| `space-1` | `4px` | 图标与文字、紧凑列表 |
| `space-2` | `8px` | 表单说明、按钮组、标签行 |
| `space-3` | `12px` | 单元格内上下间距、列表项 |
| `space-4` | `16px` | 卡片内边距、模块间距 |
| `space-5` | `20px` | 详情卡片主内边距 |
| `space-6` | `24px` | 页面区块、移动端页面边距 |
| `space-8` | `32px` | 页面标题与内容间距 |

圆角体系保持小而明确：

| 元素 | 圆角 |
| --- | ---: |
| 卡片、详情面板 | `8px` |
| 按钮、输入框、导航项、子面板 | `6px` |
| 徽章 | `4px` |
| 状态圆点、阶段节点 | 圆形 |
| 检索范围切换 | `9999px`，仅此场景允许胶囊形 |

### 5.5 边界与投影

- 默认通过 `1px solid var(--line)` 分层，不使用投影。
- 悬停只加深边框或轻灰背景，不移动卡片。
- 模态允许单层投影：`0 20px 50px rgba(31, 35, 40, 0.18)`。
- 不使用玻璃拟态、渐变背景、彩色光晕和大面积插图。

### 5.6 图标

| 场景 | 规格 |
| --- | --- |
| 导航图标 | `18px`，线宽 `1.7` |
| 按钮图标 | `16px` |
| 表格行内图标 | `16px` |
| 图标按钮 | `32px x 32px`，圆角 `6px` |

图标必须配合文字或 `aria-label`。实现新界面时优先使用统一的图标库并保持同一族图标；当前原型中的内置图标仅作为原型过渡方案。

## 6. 组件规范

### 6.1 按钮

| 类型 | 规格 | 用途 |
| --- | --- | --- |
| 主按钮 | 高 `36px`，主色填充，白字 | 新建知识库、上传文档、进入问答、提问 |
| 次按钮 | 高 `36px`，白底细边框 | 导入示例、管理知识库、取消 |
| 危险按钮 | 高 `36px`，危险色边框或填充 | 删除文档、删除知识库 |
| 轻量按钮 | 高 `32px`，透明背景 | 查看证据、查看执行过程、重试 |
| 图标按钮 | `32px x 32px` | 关闭、删除、刷新 |

规则：

- 危险确认模态内使用实心危险按钮，列表入口只使用图标或线框危险按钮。
- 禁用必须保留可见文字或提示，说明不可用原因。
- 按钮文字不换行；移动端长操作改为整行按钮时除外。
- 悬停反馈 `120ms`，按下反馈使用轻微缩放或亮度变化。

### 6.2 状态徽章

| 状态 | 文案 | 样式 |
| --- | --- | --- |
| 已就绪 | `已就绪` | 成功浅底 |
| 处理中 | `处理中` | 中性浅底加旋转指示 |
| 重复文档 | `重复文档` | 警告浅底 |
| 上传失败 | `上传失败` | 危险浅底 |
| 配置错误 | `配置错误` | 警告浅底 |
| 回答完成 | `回答完成` | 成功浅底 |
| 局部拒答 | `局部拒答` | 警告浅底 |
| 全部拒答 | `全部拒答` | 中性浅底 |
| 处理失败 | `处理失败` | 危险浅底 |

徽章必须显示文字。处理中动画在 `prefers-reduced-motion: reduce` 时停止。

### 6.3 卡片

卡片用于承载独立操作对象或面板，不在卡片内再嵌套同级卡片。

| 类型 | 内容 |
| --- | --- |
| 统计卡 | 指标名、图标、大数字、单位、一句解释 |
| 知识库项 | 名称、状态、文档数、文本块数 |
| 知识库详情 | 名称、状态、统计、主操作、上传规则、结果与文档表 |
| 会话面板 | 检索范围、消息区、输入区 |
| 证据项 | 引用号、文档名、支持状态、元信息、原文 |

卡片内边距默认 `20px`，嵌套子面板为 `14px` 至 `16px`。

### 6.4 表格

文档列表使用表格，列顺序为：

```text
文档名称 | 状态 | 文本块 | 上传时间 | 操作
```

规则：

- 桌面最小宽度 `620px`，窄屏横向滚动。
- 长文件名 `break-all`，不撑破布局。
- 数字和时间右对齐或保持等宽数字。
- 处理中文档在名称下方显示阶段步骤。
- 只有已就绪文档显示最终文本块数；处理中显示阶段，失败显示安全错误。
- 删除按钮必须带有可访问名称，例如“删除文档 产品说明.md”。

### 6.5 输入框与表单

| 元素 | 规格 |
| --- | --- |
| 单行输入 | 高 `40px`，圆角 `6px`，白底，细边框 |
| 多行输入 | 初始高 `56px`，可纵向自适应 |
| 标签 | 位于输入框上方，`14px` |
| 帮助文本 | 位于输入框下方，`13px` |
| 错误文本 | 位于输入框下方，危险色，具体说明原因 |

新建知识库必须覆盖：

- 必填。
- 去首尾空白。
- 名称重复。
- 最大长度。
- 创建失败。

### 6.6 模态框

模态用于新建和删除确认，最大宽度 `440px`。

规则：

- 打开后焦点进入第一个可交互控件。
- `Esc` 关闭，但删除确认的关闭不得触发删除。
- 遮罩点击仅关闭模态。
- 动作按钮右对齐，取消在左，确认在右。
- 删除确认必须列出不可恢复的数据范围：原始 Markdown、业务元数据、向量索引。

### 6.7 阶段流

上传阶段：

```text
校验 → 切块 → 向量化 → 保存 → 完成
```

问答阶段：

```text
问题拆分 → 检索 → 重排 → 证据判定 → 生成 → 校验 → 重新生成 → 合成回答 → 完成
```

阶段状态包括等待、进行中、已完成、未通过、已跳过。视觉采用左侧圆形节点和竖向连接线，当前节点使用主色，失败使用危险色，跳过使用弱化文本。

### 6.8 空态

空态必须说明对象价值并给出下一步操作。

| 场景 | 主文案 | 操作 |
| --- | --- | --- |
| 无知识库 | 还没有知识库 | 新建知识库 |
| 知识库无文档 | 这个知识库还没有文档 | 上传文档、导入示例资料 |
| 无已就绪文档 | 所选知识库中还没有已就绪的文档 | 前往知识库页 |
| 无会话 | 还没有提问 | 显示建议问题 |
| 无检索证据 | 没有检索到相关资料 | 无强制操作 |

空态居中放置在对应面板内部，不使用插画或装饰图形。

## 7. 页面设计

### 7.1 概览页

### 目标

让用户在 5 秒内了解当前知识资产规模，并进入知识库管理或问答。

### 结构

```text
页面标题与主操作
├── 存储统计：知识库数量、文档数量、文本块数量
├── 知识库管理入口
└── 入库规则摘要
```

### 视觉规则

- 统计卡三列排布，小屏单列。
- 数字使用 `36px` 等宽数字，单位用次级文本。
- 知识库管理入口保持白卡，不与统计卡形成同质重复。
- 入库规则使用列表而非营销卡组。

### 概览页禁止项

- 不展示运行模式。
- 不展示模型名称。
- 不展示 API Key 或密钥配置形态。
- 不展示本地绝对路径。
- 不展示评测结果或系统日志。

### 7.2 知识库页

### 目标

完成知识库和 Markdown 文档的完整生命周期管理，并让上传结果可检查。

### 桌面结构

```text
页面标题与新建操作
├── 左：知识库列表，宽 280px
└── 右：知识库详情
    ├── 名称、状态、统计、操作
    ├── 上传限制提示
    ├── 上传结果
    └── 文档列表
```

### 知识库列表

每一项显示：

- 名称。
- 当前状态。
- 文档数量。
- 文本块数量。

选中项使用主色边框和 `--primary-soft` 背景。处理中状态允许旋转指示。

### 详情操作

操作顺序从左到右为：

```text
导入示例资料 | 上传文档 | 删除知识库
```

服务配置错误或上传中时，导入和上传禁用，并通过提示说明原因。

### 上传交互

1. 用户选择一个或多个文件。
2. 前端展示每份文件的校验与处理结果。
3. 重复内容在向量化前标记为重复。
4. 成功项最终变为已就绪。
5. 部分成功时保留每份文件的独立结果。

上传结果必须区分：

| 结果 | 展示 |
| --- | --- |
| 处理中 | 当前阶段，不计入最终成功数 |
| 已就绪 | 最终成功 |
| 重复 | 未入库原因 |
| 失败 | 安全错误说明 |

结果条在用户关闭或切换知识库前保持可见。失败和重复记录不进入可检索文档表，只在结果面板中展示。

### 删除确认

删除知识库说明将删除：

- 该知识库全部文档元数据。
- 原始 Markdown 文件。
- 全部向量索引。

删除文档使用同样保守的文案，并说明删除后相关内容不再参与检索。

### 7.3 问答页

### 目标

让用户明确检索范围，得到校验后的答案，并检查证据与执行过程。

### 结构

```text
页面标题与新会话
├── 会话面板
│   ├── 检索范围选择
│   ├── 消息区
│   │   ├── 用户问题
│   │   ├── 处理中阶段流
│   │   └── 最终回答
│   │       ├── 回答状态
│   │       ├── 引用编号正文
│   │       ├── 局部拒答说明
│   │       └── 证据面板
│   └── 输入区
└── 执行过程侧栏
    ├── 当前处理状态
    ├── 当前问题
    ├── 阶段流
    └── 证据统计
```

小于 `1280px` 时执行过程侧栏移动到会话面板之后，保持单列阅读顺序；大于等于 `1280px` 时侧栏固定在右侧，实时跟踪最新一次提问。

### 检索范围

- 每个知识库是一个可多选的范围标签。
- 选中标签使用主色浅底和复选状态。
- 未选择任何知识库时禁用输入和提问。
- 空态提供“前往创建”链接。
- 范围变化不修改已生成消息的审计记录。

### 会话空态

空态展示证据问答规则和来自已就绪文档的建议问题。建议问题最多 4 条，单列排布，避免用户被示例淹没。

### 处理中

- 不显示 token 级正文。
- 不显示提示词。
- 使用阶段流表达当前进度。
- 文案明确“校验完成后再显示回答”。
- 服务安全错误时显示保守失败说明和重试入口。

### 最终回答

回答卡片按以下顺序组织：

1. 回答状态徽章。
2. 答案正文，引用编号与证据面板编号一致。
3. 局部拒答列表。
4. 展开按钮：查看证据、查看执行过程。

局部拒答提示使用警告浅底和左侧色条，明确列出缺少充分证据的子问题。全部拒答使用中性状态，不生成答案正文。

### 证据面板

每条证据包含：

| 字段 | 展示 |
| --- | --- |
| 引用编号 | 方形编号，例如 `[1]` |
| 文档名 | 可换行 |
| 证据状态 | 回答证据 或 相关资料，不足以直接回答 |
| 标题路径 | 完整路径 |
| 分数 | 等宽数字 |
| 子问题 | 对应拆分后的子问题 |
| 原文 | 左侧细线的引用块 |

`supporting` 证据与答案引用编号强关联。`related` 证据只说明相关，不暗示已支持答案。

### 执行过程侧栏

- 空态显示“等待提问”，说明回答过程与引用证据的展示位置。
- 提问后始终跟踪最新一次助手处理，不切换或截断历史消息。
- 阶段流包含问题拆分、检索、重排、证据判定、生成、校验、重新生成与合成回答。
- 统计区展示回答证据、相关资料、可回答子问题和候选证据数量。
- 处理失败时展示安全错误摘要，不显示底层异常、提示词或密钥。

### 输入区

- 输入框固定在会话面板底部，与消息区同步增长。
- 输入框宽度与会话面板内宽对齐，不再额外收缩到固定正文宽度。
- `Enter` 提交，`Shift + Enter` 换行。
- 中文输入法组词期间 `Enter` 不提交。
- 未选范围时禁用输入并显示原因。
- 处理中禁用重复提交。
- 按钮仅在有问题文本且范围有效时可用。

## 8. 关键状态矩阵

| 场景 | 状态 | 界面要求 |
| --- | --- | --- |
| 服务 | 连接中 | 全局状态徽章显示连接中 |
| 服务 | 已连接 | 全局状态徽章显示服务已连接 |
| 服务 | 配置错误 | 禁用上传、导入、提问，并显示安全提示 |
| 服务 | 索引异常 | 禁用上传、导入、提问，并提示检查数据一致性 |
| 服务 | 服务异常 | 显示服务异常，避免暴露底层异常 |
| 知识库 | 空库 | 空态引导新建 |
| 知识库 | 处理中 | 状态徽章和上传阶段可见 |
| 知识库 | 索引异常 | 状态徽章提示，详情给出下一步 |
| 文档 | 校验失败 | 结果面板显示安全错误，不进入文档表 |
| 文档 | 重复 | 结果面板显示重复，不调用向量化 |
| 文档 | 处理中 | 名称下方显示阶段 |
| 文档 | 已就绪 | 文档表显示最终 chunk 数 |
| 上传 | 部分成功 | 每份文件独立结果，不互相覆盖 |
| 问答 | 未选范围 | 输入禁用并说明原因 |
| 问答 | 空会话 | 建议问题和证据规则 |
| 问答 | 处理中 | 阶段流，无正文预览 |
| 问答 | 回答完成 | 正文加引用编号 |
| 问答 | 局部拒答 | 有证据部分回答，其余列入拒答 |
| 问答 | 全部拒答 | 不生成正文，说明证据不足 |
| 问答 | 处理失败 | 安全错误与重试 |

## 9. 文案规范

### 9.1 语气

- 直接说明对象和动作，不使用拟人化寒暄。
- 错误文案必须包含用户可理解的原因和下一步。
- 不承诺未经验证的能力。
- 不把相关资料表述为答案依据。

### 9.2 推荐文案

| 场景 | 文案 |
| --- | --- |
| 概览说明 | 查看知识库存储情况并进入常用操作。 |
| 空知识库 | 知识库是独立的检索范围。创建后可以上传 Markdown 文档并在问答中使用。 |
| 上传限制 | 仅支持 UTF-8 Markdown，单文件不超过 5 MB，单次最多 20 个文件。 |
| 重复文档 | 知识库内已有相同内容，未重复入库。 |
| 删除知识库 | 删除后无法恢复，相关内容不再参与检索。 |
| 未选知识库 | 请先选择至少一个知识库。 |
| 处理中 | 校验完成后再显示回答。 |
| 全部拒答 | 所选知识库中没有足够证据回答这个问题，因此没有生成回答。 |
| 局部拒答 | 以下部分缺少充分证据，未作回答。 |
| 相关资料 | 相关资料，不足以直接回答。 |

### 9.3 禁止文案

禁止出现：

- API Key、密钥形态、模型服务商细节。
- 本地绝对路径。
- 提示词内容。
- 底层堆栈或原始异常。
- “离线模式”或“演示模式”。
- 未连接后端的 UI 原型说明。

产品正式名称使用“本地 RAG 知识库工作台”。导航或品牌区可使用简短名称“RAG 工作台”，不引入与 PRD 无关的新品牌名。

## 10. 动效

| 场景 | 动效 | 时长 |
| --- | --- | ---: |
| 按钮悬停 | 背景或边框变化 | `120ms` |
| 展开证据或过程 | 高度过渡或直接显示 | `120ms` 至 `160ms` |
| 处理中徽章 | 旋转指示 | `800ms` 循环 |
| 当前阶段 | 透明度轻脉冲 | `1200ms` 循环 |
| 消息滚动 | 自动滚动到最新消息 | 平滑滚动 |

动效只改变 `opacity`、`transform` 和颜色，不改变布局尺寸。所有循环动效必须在 `prefers-reduced-motion: reduce` 下停止，自动滚动改为即时定位。

## 11. 可访问性

### 11.1 键盘

- 全部按钮、输入、表格操作、范围切换可键盘访问。
- 焦点样式统一为 `2px solid var(--primary)` 加 `2px` 偏移。
- 模态管理焦点和 `Esc`。
- 展开面板按钮使用 `aria-pressed`。

### 11.2 语义

| 组件 | 语义 |
| --- | --- |
| 主导航 | `nav` 加 `aria-current="page"` |
| 服务状态 | `role="status"` |
| 检索范围 | `role="checkbox"` 加 `aria-checked` |
| 会话回答 | `aria-live="polite"` |
| 上传阶段 | 有语义标签的 `ol` |
| 证据列表 | `ul` 和明确字段 |
| 删除图标 | 带 `aria-label` 的按钮 |

### 11.3 可读性

- 不低于 `13px` 的界面文本。
- 正文和表格保持足够行距。
- 长文件名、知识库名、标题路径允许换行。
- 颜色状态必须配合文字。
- 证据原文保持可选中、可复制，方便人工审计。

## 12. 安全与隐私界面规则

1. 全局服务状态只表达连接中、已连接、配置错误、索引异常、服务异常。
2. 配置错误禁用入库、导入和问答，不显示配置项值。
3. SSE 阶段事件只展示业务阶段和安全摘要。
4. 未验证答案不进入会话正文。
5. 技术错误详情仅写入本地安全日志，界面显示用户可行动信息。
6. 删除确认必须描述元数据、原始文件和向量都会删除。
7. 文档、证据、执行过程不显示本地路径。

## 14. 与现有原型的差距

| 差距 | 设计要求 |
| --- | --- |

## 15. UI 验收清单

- 三个导航入口在任何页面保持可见且当前项可识别。
- 概览页三项统计与真实数据一致，不显示敏感配置。
- 无知识库、无文档、无已就绪文档的空态完整。
- 新建、重复、删除、上传、提问的可用与禁用状态清晰。
- 单文件失败不影响同批其他文件展示。
- 重复文档未入库且不被检索。
- 文档表状态、chunk 数、时间、删除入口完整。
- 删除确认说明全部数据范围。
- 问答范围选择不影响历史消息记录。
- 未选知识库时无法提问。
- 处理中只显示阶段流，不显示正文。
- `answer_final` 之前不出现答案正文。
- 引用编号与证据编号一致。
- 证据面板明确区分回答证据和相关资料。
- 局部拒答列出未回答子问题。
- 全部拒答不生成正文。
- 界面不出现 API Key、模型名、本地路径、提示词或底层异常。
- 键盘可完成新建、上传、删除、提问、展开证据。
- 状态动画响应减少动态偏好。
- `375px`、`768px`、`1024px`、`1440px` 下无文本重叠和横向意外溢出。

## 16. API DTO 与 SSE 契约对齐

后端接口字段、错误码和 payload 的唯一事实来源是 `TECHNICAL_DESIGN.md` 第 13 节。前端只依赖以下 DTO 和事件名，不直接依赖 SQLite、Chroma、Provider、prompt 或本地路径。

### 16.1 API 与 DTO

| 接口 | 方法 | 请求 DTO | 响应 DTO |
| --- | --- | --- | --- |
| `/api/status` | `GET` | 无 | `SystemStatus` |
| `/api/knowledge-bases` | `GET` | 无 | `KnowledgeBaseSummary[]` |
| `/api/knowledge-bases` | `POST` | `KnowledgeBaseCreate` | `KnowledgeBaseSummary` |
| `/api/knowledge-bases/{kb_id}` | `DELETE` | 无 | `204 No Content` |
| `/api/knowledge-bases/{kb_id}/documents` | `GET` | 无 | `DocumentSummary[]` |
| `/api/knowledge-bases/{kb_id}/documents` | `POST` | multipart files | `DocumentBatchResult` |
| `/api/knowledge-bases/{kb_id}/documents/{document_id}` | `DELETE` | 无 | `204 No Content` |
| `/api/knowledge-bases/{kb_id}/import-demo` | `POST` | 无 | `DocumentBatchResult` |
| `/api/chat/stream` | `POST` | `ChatRequest` | SSE `SseEvent` |

字段边界：

| DTO | UI 使用的字段 |
| --- | --- |
| `SystemStatus` | `status`, `knowledge_base_count`, `document_count`, `chunk_count`, `limits` |
| `KnowledgeBaseSummary` | `id`, `name`, `document_count`, `chunk_count`, `created_at` |
| `DocumentSummary` | `id`, `kb_id`, `filename`, `status`, `chunk_count`, `created_at` |
| `DocumentBatchResult` | `documents`, `errors` |
| `ChatRequest` | `question`, `history`, `kb_ids` |
| `SseEvent` | `type`, `stage`, `message`, `sequence`, `payload` |

`DocumentSummary.status` 第一版只有 `ready`。上传结果中的处理中是前端本地状态；服务端返回后，成功项进入 `documents`，重复和失败项只进入 `errors`。

### 16.2 全局状态映射

| 后端状态 | UI 展示 | 行为 |
| --- | --- | --- |
| 请求未完成 | 连接中 | 显示加载态 |
| `ready` | 已连接 | 启用正常操作 |
| `configuration_missing` | 配置错误 | 禁用上传、导入和提问 |
| `storage_inconsistent` | 索引异常 | 禁用上传、导入和提问，提示检查数据一致性 |
| 网络失败、`internal_error` 或未分类错误 | 服务异常 | 显示安全错误与重试 |

`连接中` 是前端本地状态，不是 API 状态值。

### 16.3 SSE 事件名

前端只处理以下事件：

| `type` | UI 行为 |
| --- | --- |
| `stage_started` | 将对应阶段标记为进行中 |
| `stage_completed` | 将对应阶段标记为已完成或未通过 |
| `evidence` | 更新证据面板；区分 `supporting` 与 `related` |
| `decision` | 更新每个子问题的可回答状态和缺失信息 |
| `answer_final` | 校验完成后渲染答案正文、分段状态和引用 |
| `completed` | 结束处理中状态 |
| `error` | 显示安全错误并结束请求 |

阶段名与文案固定映射：

| `stage` | UI 文案 |
| --- | --- |
| `decompose` | 问题拆分 |
| `retrieve` | 检索 |
| `rerank` | 重排 |
| `judge` | 证据判定 |
| `generate` | 生成 |
| `validate` | 校验 |
| `regenerate` | 重新生成 |
| `compose` | 合成回答 |

`completed` 是终态事件，不是阶段名，不进入阶段流节点。

### 16.4 答案与证据状态

- `answer_final.parts[].status` 只使用 `verified` 和 `refused`。
- `answer_final.refused=true` 仅用于全部子问题拒答。
- 存在已验证部分和拒答部分时，界面显示“局部拒答”。
- `evidence[].support_status` 只使用 `supporting` 和 `related`。
- 引用编号使用 `reference_id`，必须与答案 `citations` 一致。
- 收到 `answer_final` 前不渲染任何答案正文。

## 17. 交付边界

本文档覆盖 UI 设计规范、交互状态和前端契约映射，不定义后端接口实现、模型调用质量指标、CLI 行为或数据库结构。相关产品要求以 `PRD.md` 为准；接口字段与 payload 的完整定义以 `TECHNICAL_DESIGN.md` 为准。
